# Relational Inductive Biases for BabyLM 2026 Pretraining

This repository contains the training code and exact experiment recipes for
four DeBERTa-v2 masked language models trained on the BabyLM 2026 Strict-Small
corpus:

- **Standard MLM**: the matched masked-language-modeling baseline.
- **Syntagmatic**: aligns a masked representation with an
  attention-weighted summary of relevant context tokens.
- **Paradigmatic**: aligns a masked representation with the centroid of the
  target token's embedding neighbors.
- **Relay Joint**: combines both objectives using fixed representation slices,
  a staged handoff, and an entity representation anchor.

The auxiliary objectives use signals generated by the model itself. They do
not require additional annotations, external linguistic resources, or extra
trainable parameters.

### Directory details

`experiments/claim_compagg_2026/` contains the canonical launch scripts. The
three `common*.sh` files define shared architecture, optimization, masking,
data-path, and checkpoint settings. The four `run_*.sh` files add the
method-specific objective flags.

`pretraining_progress/` contains the two trainers. The standard, Syntagmatic,
and Paradigmatic configurations use `train_clean_mlm_rae_v7_compagg_progress.py`.
Relay Joint uses `train_clean_mlm_rae_v7_compagg_v14_subspace_route.py`.

`model_snapshots/` contains the exact `train_code.py`, `run_cmd.sh`, and
`claim_manifest.txt` saved with each seed-0 model. These files are provenance
snapshots. Use the canonical scripts under `experiments/` to launch new runs.

`data/` contains the upstream dataset description and citation. The corpus
itself is not committed to this repository. Instructions for reproducing the
exact train/dev split are below.

`tokenizers/` contains the 40,000-token SentencePiece model used by all four
configurations.

`docs/` contains result summaries and checkpoint provenance notes from the
original experiments. Some provenance notes retain the absolute paths from the
original training machine.

## Shared training configuration

| Setting | Value |
|---|---|
| Backbone | DeBERTa-v2, 12 layers, 12 attention heads |
| Hidden / FFN size | 384 / 1280 |
| Parameters | 34,677,952 |
| Tokenizer | SentencePiece, 40,000 tokens |
| Training corpus | BabyLM 2026 Strict-Small, 10M words |
| Epochs | 10 (at most 100M cumulative words) |
| Sequence curriculum | length 64 for epochs 1-5; 256 for epochs 6-10 |
| Batch size | 256 |
| Optimizer | LAMB |
| Peak learning rate | 0.007 |
| Learning-rate schedule | 1% warmup, cosine decay |
| MLM probability | linear decay from 0.40 to 0.15 |
| Token replacement | 80% mask, 10% random, 10% unchanged |
| Seeds | 0, 1, 42 |

## Setup

Clone the repository and create a Python environment:

```bash
git clone https://github.com/yywhsgnd/babylm_2026.git
cd babylm_2026

python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

An NVIDIA GPU and a CUDA-compatible PyTorch installation are recommended.
The launch recipes enable the bitsandbytes LAMB optimizer.

## Prepare the data

Download the official BabyLM 2026 Strict-Small dataset:

```bash
git clone \
  https://huggingface.co/datasets/BabyLM-community/BabyLM-2026-Strict-Small \
  data/BabyLM-2026-Strict-Small
```

Reproduce the exact split used by the experiments. The first five sources and
the first 892 Switchboard lines form the training file. The remaining 2,000
Switchboard lines form the development file.

```bash
cat \
  data/BabyLM-2026-Strict-Small/bnc_spoken.train.txt \
  data/BabyLM-2026-Strict-Small/childes.train.txt \
  data/BabyLM-2026-Strict-Small/gutenberg.train.txt \
  data/BabyLM-2026-Strict-Small/open_subtitles.train.txt \
  data/BabyLM-2026-Strict-Small/simple_wiki.train.txt \
  > data/bb26_strictsmall.train

head -n 892 \
  data/BabyLM-2026-Strict-Small/switchboard.train.txt \
  >> data/bb26_strictsmall.train

tail -n 2000 \
  data/BabyLM-2026-Strict-Small/switchboard.train.txt \
  > data/bb26_strictsmall.dev
```

Verify the exact files:

```bash
sha256sum data/bb26_strictsmall.train data/bb26_strictsmall.dev
```

Expected output:

```text
fd5f0c7ca5ab1fe12cdd8c7041bc2fb514548e8557357b5bd8c80cd4a16bd7fe  data/bb26_strictsmall.train
6111dd6182b1c3ff0080edf3357cd52f528d934dfb6e562d5bbf440af84474f7  data/bb26_strictsmall.dev
```

## Run an experiment

Run commands from the repository root. The final positional argument is the
random seed, and `GPU` selects the visible CUDA device.

### Standard MLM

```bash
GPU=0 bash experiments/claim_compagg_2026/run_00_clean.sh 0
```

### Syntagmatic

```bash
GPU=0 bash experiments/claim_compagg_2026/run_31_comp_entguard.sh 0
```

### Paradigmatic

```bash
GPU=0 bash experiments/claim_compagg_2026/run_41_agg_synonly.sh 0
```

### Relay Joint

```bash
GPU=0 bash \
  experiments/claim_compagg_2026/run_222_compagg_v22_v15_relay_synp050_synkeep010.sh \
  0
```

To reproduce all three seeds for one configuration sequentially:

```bash
for seed in 0 1 42; do
  GPU=0 bash experiments/claim_compagg_2026/run_41_agg_synonly.sh "$seed"
done
```

To run the three seeds in parallel on three GPUs:

```bash
GPU=0 bash experiments/claim_compagg_2026/run_41_agg_synonly.sh 0 &
GPU=1 bash experiments/claim_compagg_2026/run_41_agg_synonly.sh 1 &
GPU=2 bash experiments/claim_compagg_2026/run_41_agg_synonly.sh 42 &
wait
```

## Outputs

Each launch script creates:

```text
models/<model-name>/
|-- chck_1M/ ... chck_100M/
|-- train_code.py
|-- run_cmd.sh
`-- claim_manifest.txt

log/<model-name>.log
```

The final pretrained model is `models/<model-name>/chck_100M`. Intermediate
checkpoints are retained because the recipes enable `--all_checkpoints`.
Ensure that sufficient disk space is available before training.

The exact model-name prefixes are:

| Configuration | Output prefix |
|---|---|
| Standard MLM | `bb26_claim_clean_s<seed>` |
| Syntagmatic | `bb26_claim_comp_entguard_s<seed>` |
| Paradigmatic | `bb26_claim_agg_synonly_s<seed>` |
| Relay Joint | `bb26_claim_compagg_v22_v15_relay_synp050_synkeep010_s<seed>` |

## Evaluation

Evaluate `chck_100M` with the official
[BabyLM evaluation pipeline](https://github.com/babylm-org/babylm-eval). The
original experiments used pipeline commit
`3d57ddc8c40ee795c0b5e41b3a20251a9457a593`.

The evaluation pipeline is maintained separately and is not vendored here.
Follow its Strict-Small instructions and provide the path to the desired
`models/<model-name>/chck_100M` directory.
